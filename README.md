# @asyst/atlas

React components and design tokens of the **Atlas Design System** by Asyst.
Built with Tailwind CSS v4 and Radix primitives.

## Install

Atlas is distributed from GitHub, not the npm registry:

```bash
npm install github:androsap/atlas-design-system#semver:^0.2.0
```

- `#semver:^0.2.0` — follow compatible releases (recommended)
- `#v0.2.0` — pin an exact version
- `#release` — latest build

The dependency is still named `@asyst/atlas` in your `package.json`, so
imports are `from "@asyst/atlas"`. If the repository is private, the
installing machine needs GitHub access (SSH key or a token).

Peer dependencies: `react >= 18`, `react-dom >= 18`, `tailwindcss >= 4`.

## Setup

In your global stylesheet, import the tokens **before** Tailwind and let
Tailwind scan the package so the classes the components use are generated:

```css
@import "@asyst/atlas/tokens.css";
@import "tailwindcss";

@source "../node_modules/@asyst/atlas/dist"; /* path relative to this CSS file */
```

Dark mode: `<html data-theme="dark">`.

## Usage

```tsx
import { Button, Badge, Input } from "@asyst/atlas"
import { Plus } from "lucide-react"

<Button color="brand" variant="primary" leadingIcon={Plus}>Create</Button>
```

Token values in JS/TS:

```ts
import { primary500, size16 } from "@asyst/atlas/tokens"
```

## What's in the package

| Export                       | Contents                                                        |
| ---------------------------- | --------------------------------------------------------------- |
| `@asyst/atlas`               | All components, their prop types, `cn()`                        |
| `@asyst/atlas/tokens`        | Design tokens as JS constants                                   |
| `@asyst/atlas/tokens.css`    | Primitive + semantic CSS variables and the dark theme           |
| `@asyst/atlas/llms.txt`      | Generated component reference for AI coding assistants          |

Interactive components ship with `"use client"`; the rest (Button, Badge,
Input, Textarea, Spinner, Breadcrumbs) also work in React Server Components.

## Development (in this repo)

```
packages/atlas/
├── src/
│   ├── components/      # one file per component
│   ├── lib/             # cn(), calendar helpers, mergeRefs
│   ├── styles/
│   │   ├── tokens.css   # generated by style-dictionary — don't edit
│   │   └── theme.css    # semantic tokens + dark theme
│   ├── tokens.ts        # generated by style-dictionary — don't edit
│   └── index.ts         # public API — export every component here
├── tokens/              # Tokens Studio JSON (source of truth for tokens)
├── scripts/generate-llms.mjs
└── tsup.config.ts
```

| Command (from repo root)            | What it does                                              |
| ----------------------------------- | --------------------------------------------------------- |
| `npm run build:atlas`               | tsup → `dist/` (ESM + .d.ts), `tokens.css`, `llms.txt`     |
| `npm run dev:atlas`                 | Rebuild on change (run next to `npm run dev`)             |
| `npm run tokens:build`              | Regenerate `tokens.css` / `tokens.ts` from `tokens/*.json` |
| `npm run changeset`                 | Record a patch / minor / major change for the next release |

### Adding a component

1. Create `src/components/<name>.tsx` (add `"use client"` if it uses hooks or browser APIs).
2. Use relative imports with a `.js` extension (`import { cn } from "../lib/utils.js"`).
3. Export the component **and** its `Props` type from `src/index.ts` — `llms.txt` is generated from these exports.
4. Run `npm run changeset` and choose `minor`.

### Releasing

Merging to the main branch runs `.github/workflows/release.yml`:
Changesets opens a "Version Packages" PR; merging it bumps the version and
updates `CHANGELOG.md`, then the workflow commits the built package to the
`release` branch, tags it `v<version>`, and deploys the docs site. Nothing is
published to npmjs (the package is marked `private` to prevent that).
